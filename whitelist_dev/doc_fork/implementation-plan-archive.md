# 实施方案归档（Archive）

## 文档定位

这份文件是历史实施方案的归档版本，对应早期为 `whitelist_mode` 功能编写的落地计划。

它保留的价值主要有两点：

- 帮助回顾这组能力最初是如何拆分成代码改动点的
- 方便理解这个 fork 为什么会对 `whitelist_mode` / `force_manage` 相关流程这么关注

## 为什么归档

这份文档不再适合作为当前开发的直接执行手册，原因包括：

- 文档写作时，很多步骤仍处于“待实施”状态
- 其中包含明显带风险的回滚建议，例如直接使用 `git checkout .`、`git clean -fd`
- 一些验证命令和工作流描述偏向当时的单次实施环境，不适合直接复用
- 当前仓库状态已经和文档撰写时不同，继续把它当成“现行方案”容易误导

## 当前应如何使用它

建议把这份归档只当成：

- 历史背景材料
- 功能拆分参考
- 变更动机说明

不建议把它当成：

- 当前代码的权威说明
- 当前操作步骤手册
- 当前排障文档

## 当前权威来源应该看哪里

如果你要理解当前 fork 的真实行为，优先看：

- `whitelist_dev/doc_fork/project-analysis.md`
- `whitelist_dev/doc_fork/advanced-usage-guide.md`
- `whitelist_dev/doc_fork/example-configurations.md`
- 当前源码中的实际实现

## 和原始文件的关系

本归档文档来自：

- `whitelist_dev/implementation_plan.md`

原文件仍然保留，原因是：

- 它包含较完整的历史拆解过程
- 某些小节对理解设计意图仍有帮助

但后续如果继续维护类似文档，建议新文档直接写成：

- 当前状态说明
- 已验证结果
- 风险点
- 后续迭代建议

而不是继续使用“待执行 checklist”风格。

## 归档结论

这份文档的状态应被视为：

- 历史记录：是
- 当前实施手册：否
- 当前事实来源：否
